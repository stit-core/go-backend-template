# Тесты

Процедура (добавить мок для интерфейса, тесты при скаффолде блока) — skill `scaffold`.
E2E/smoke-харнес (pytest, side-effect-ассерты) — `test/README.md`. Здесь — инварианты.

## Тест проверяет поведение

- Утверждай результат, ошибку (`require.ErrorIs`) и эффекты: вызовы портов с точными
  аргументами, запись в БД, событие (`outboxtest.Recorder`), исход метрики (провайдер теста
  `metrictest.NewProvider`, значение — `require.InDelta`). `NotNil` ради покрытия — не тест:
  тест или fuzz-цель без утверждений в любом пакете модуля ловит archtest `TestTestsAssert`, пустышку —
  `/code-review`.
- Рядом с happy path — error path и граница (пусто, максимум, чужой id).
- Красный тест не подгоняй под код: сначала реши, кто прав; меняешь ожидание — причина в теле
  коммита.

## Структура и стиль

- `<file>_test.go` рядом с `<file>.go`. Package `<pkg>_test` (black-box); `<pkg>`
  (white-box) — только для приватных функций, редко.
- **Ассерты — `require`** (`stretchr/testify/require`) + `handlertest.Assert*` в
  handler-тестах. `assert` и голые `t.Fatalf`-сравнения не используем.
- **Таблица — slice анонимных struct + `t.Run(tc.name)`**. Сценарии одной функции, различающиеся
  данными → table-driven `Test<Method>`; существенно разный arrange (другие моки/фикстуры) или
  одиночный сценарий → `Test<Method>_<Scenario>`. Переиспользуемая таблица семейства методов —
  named type + shared var допустимы.
- **`t.Parallel()`** — в каждом юнит-тесте и сабтесте; в integration — в каждом тесте (у теста свой
  контейнер), его сабтесты делят БД и идут подряд. Fuzz — без.
- Сообщения ошибок в тестах — английский.
- Часы: `clockkit.NewFixed(time.Date(...))` с литеральной датой — не `NewFixed(time.Now())`.

## Что обязано иметь тест (минимум слоя)

| Слой | Тест |
|---|---|
| `policy.go` | unit table-driven |
| `entity.go` (конструкторы/методы) | unit; +fuzz (`entity_fuzz_test.go`) при строковых валидациях |
| `usecase.go` | unit через строгие моки портов и настоящую policy, fixture `newUC(t, …)` |
| `delivery/http` | handler-тест через `golibinfra/testkit/handlertest` (операции под `Security` — `handlertest.WithSecuritySchemes(authgate.CookieScheme(identitytest.Extract))`, личность — ctx запроса): happy path каждой операции — точный вход usecase и тело ответа; `errors_test.go` (white-box): таблица операции объявляет ошибки её usecase (список — по коду usecase); без 500 и без таблицы операции вне `Declare` — archtest `TestDomainErrorTables` |
| `delivery/nats` | unit handler-функции (мок Usecase-порта) — включая дубль-доставку; контракт с поставщиком — `contract_test.go` (rule `events-and-messaging`) |
| `module/adapters.go` | unit (white-box) поверх `Trusted` поставщика: маппинг полей, ctx вызывающего до `Trusted` (запись и чтение под блокировкой — в его транзакции) и каждая ошибка вызываемого метода (`TrustedErrors[метод]`) → sentinel потребителя |
| `infra/<kit>/` | unit на настоящем ките или фейке из `testkit` |
| `trusted.go` | unit через моки портов; метод отдаёт ровно свою строку `TrustedErrors` (`return` в методах `Trusted` — archtest) |
| `infra/postgres/repository.go` | integration (build-tag) на каждый метод: запись видна чтением, условия SQL (версия, удалённые, регистр, фильтр, страница); битый id — sentinel «нет такого» (id не от клиента — ошибка), сбой БД (отменённый ctx) — ошибка с причиной, не sentinel домена |
| fx-граф | `cmd/api/main_test.go` `fx.ValidateApp`, корню графа `context.Context` не доступен; `fx.As` нет — archtest |
| HTTP API | `cmd/api/api_test.go`: API проходит проверку старта httpkit (`Security` или `httpkit.Public`, уникальный метод+путь), операция без пометки — ошибка старта, пути операций доменов — под `/api/`, открыты ровно `publicOperations` (открыть операцию — правка списка), под `Security` — коды 401 сессии; `openapi.json` совпадает с кодом |
| подкоманды `main` | `cmd/api/healthcheck_test.go`: тестовый бинарь, перезапущенный как `api healthcheck` (`TestMain` зовёт `main`), — код выхода по `/health` на `HTTP_ADDR`, сервис не стартует; `cmd/api/main_test.go`: тот же бинарь как `api` без окружения — отказ старта в логе сервиса (JSON, ERROR с причиной), а не в консоли fx |
| запуск сервиса | `cmd/api/boot_test.go` (integration): граф `main` на контейнерах с env из `.env.example` стартует и останавливается, как в проде (память Argon2 — лёгкая, `ARGON2_MEMORY_KIB`: параметры кита по умолчанию проверяет smoke релиза); свойство сервиса целиком (не домена) — проверкой в `TestBoot` |
| команда миграций | `cmd/migrate/run_test.go` (integration): каждая подкоманда (`up`, `down`, `version`, ремонт dirty) — на источниках китов и каталоге приложения |
| домены идентичности | `cmd/api/identity_test.go` (integration): поток через несколько доменов, хранилище кита и секреты вне лога и таблиц — сквозь HTTP на графе `main` (`TestIdentity`, `TestSessions`); `cmd/seed-admin/main_test.go` — повышение админа |

E2E (`test/`, `make e2e`) — сквозные потоки на собранном стеке: вход и сессии, права, событие между
доменами. Новой ручке хватает handler-теста, сценарий e2e — когда она меняет такой поток. `make e2e`
в гейт не входит, `make e2e-smoke` (тесты `smoke`: boot, вход и сессии, права, событие) гоняет `make release`;
оба сначала гоняют `ruff check` и `mypy` харнеса.

## TDD для багфиксов — обязательно

RED→GREEN: падающий тест, воспроизводящий баг → фикс → зелёный → оба файла одним коммитом.
Тест должен падать по той причине, что и баг. Ведёт это skill `triage-failure`.

## Моки и фикстуры (mockery v3)

- Конфиг — `.mockery.yml`: интерфейсы из `usecase.go` и `delivery/*` (Usecase-порты), кроме
  policy-порта `Authorizer` — у него мока нет, тесты берут настоящую policy, — и портов с
  рукописным фейком (ниже).
  Файлы: `mocks/<interface_snake>.go` (пакет `mocks`, тип `Mock<Interface>`). Регенерация —
  `make gen`; `make gen-check` ловит дрейф и untracked-моки.
- **Изоляция (archtest)**: пакет `mocks` любого домена импортируется только из `*_test.go`.
- Template `testify` даёт `EXPECT()`-API; `t` в конструкторе — авто-`AssertExpectations`.
- **Fixture usecase-теста** — `newUC(t, …)`: порты — строгие моки без ожиданий (вызов, которого
  кейс не ждёт, — провал), policy — настоящая (`NewPolicy()`): право решает identity кейса.
  Ожидание побочного эффекта — с точными аргументами и `.Once()`, без `.Maybe()` (ожидание без `.Once()`,
  `.Twice()` или `.Times(n)` — и в цепочке, продолженной через переменную, — и `.Maybe()` — отказ `TestTestsAssert`);
  запись в транзакции — `mock.MatchedBy(pgkit.InTx)`; событие — `Recorder.Last(subject)`, лишних нет —
  `Count()`. Порт кейс передаёт параметром, несколько портов — functional options `withX(...)`.
- Рукописный фейк вместо мока — у протокольного порта (stateful: цепочки insert/markUsed) и у
  чистого порта без эффектов (выпуск access-токена `auth.Tokens`: ответ выводится из входа, тест сверяет
  его в результате — строгий мок закреплял бы факт и число вызовов на каждом пути, а не результат);
  тогда интерфейс из `.mockery.yml` убирается — мок и фейк вместе не живут.
- Identity-контексты — `internal/testkit/identitytest` (`Admin`/`Client`/`Anon`), не
  inline `identity.With(...)`: это ctx запроса с IP клиента и ID (`identitytest.IP`, `RequestID`),
  с ними тест сверяет аудит, guard входа и лимитер.

## Интеграционные

- Build-tag `//go:build integration` сверху файла; гоняются в `make check` (шаг `make test-int`).
  Docker обязателен: вне `-short` testkit без Docker роняет тест, а не пропускает его.
- Другого ограничения сборки в репо нет: только `//go:build integration` и только у `*_test.go`, без
  суффиксов ОС и архитектуры в имени (archtest `TestBuildConstraints`) — иначе файл выпал бы из vet,
  lint, тестов и покрытия гейта или из образа; шаг build собирает `./...` без тегов, как образ.
- Контейнер+миграции+пул — `golibinfra/testkit.StartPostgres(t, testkit.WithMigrationsDir(path))`
  (нужна kit-таблица → ещё `testkit.WithMigrations(<kit>pg.Migrations)`);
  канон — `internal/domain/user/infra/postgres/repository_test.go`. Seed-хелперы строк
  поверх — `internal/testkit/pgseed`.

## Coverage

`make cover-check` (шаг `make check`, pre-push) — профиль одного прогона `make test-int` (юнит +
integration, `-coverpkg`) по `internal/`, `pkg/` и `cmd/`: сгенерированное (заголовок `Code generated … DO NOT
EDIT.` — только вывод sqlc и mockery: в другом месте заголовок, а в каталоге вывода sqlc — чужой файл не пускает
archtest) и тестовая обвязка `internal/testkit/` вне scope, fx-провайдеры засчитывает boot-тест `cmd/api`. Порог —
факт, 100% statement'ов `internal/` и `pkg/`: красный, если хоть один блок не исполнен; функция, которую тесты не
исполнили (пустое тело — исполнено ли оно), — красный и в `cmd/`, кроме `main` (корень процесса: его исполняют
перезапущенный тестовый бинарь и образ, профиль этого не видит; поэтому `main` — только вход, логика в нём и
литерал функции на уровне пакета `cmd/` — его тело вне функций профиля — отказ archtest `TestMainOnlyEnters`);
`init()` кода (не теста) не пускает lint
(`gochecknoinits`): загрузка пакета исполнила бы его без теста. Отказ называет блоки и функции (все блоки —
`make cover-check FORMAT=detailed`). Блок, который тесты не исполнят по построению, — запись списка
непокрываемого `scripts/tools/cover.sh` с причиной: пополнить его — ослабить гейт (CLAUDE.md § Сначала
спросить); запись — ровно один свой неисполненный блок (без текста, без такого блока или с несколькими —
отказ), и функцию без тестов она не прячет. Покрытие — осмысленными тестами: силу держат мутации (ниже), а
не процент.

## Мутации

`make mutate` (вне гейта, нужны Docker и python3): правки «было → стало» из `scripts/tools/mutants.txt` — по тексту
кода, без номеров строк, — по одной на исполнителя в его worktree (`.cache/mutate/wt`, `wt-2`, …) по снимку рабочего
дерева (отслеживаемые файлы с незакоммиченными правками и новые в индексе, и `git add -N`; неотслеживаемые не входят):
спецификацию и код проверяют до коммита, само дерево разработчика прогон не трогает. Исполнителей — половина ядер слота
и не больше, чем помещается в доступную память (`MUTATE_JOBS` — явно); строки хода и итог — в порядке спецификации,
как у одного. Затем компиляция всех пакетов без линковки (программа, чей файл задела правка, ещё и линкуется), юнит- и
integration-тесты пакетов, кроме `internal/archtest`, и он последним: его кеш go test снимает любая правка, а поломку
логики он видит редко; убитая им — юнит-стадия, а мутацию, которую убили бы и он, и integration, убивает integration;
archtest с тегом integration при тех же файлах его теста — один раз. Серверы integration раннер поднимает один раз на
прогон (общий режим golibinfra testkit, `TESTKIT_SHARED`): у теста — своя база Postgres, сервер NATS, Redis или MinIO
в аренде и чистый; контейнеры прогона — с меткой `mutate.run=<прогон>` и именем `mutate-<прогон>-…` — снимаются в
конце и при обрыве, оставленные убитым раннером — следующим прогоном репо (метка `mutate.repo`). Вердикт — тот же, что
у `go test ./...` стадии на контейнере на вызов; итог — убитые и выжившие списком, код 1 при новых выживших и
таймаутах, с `A=--strict` (шаг релиза) — ещё при устаревших якорях, несобравшихся правках, эквивалентных, которые
тесты убили, и файлах кода без мутаций: спецификация, разошедшаяся с кодом, меряет меньше. Выжившая — пробел теста:
тест, который её убивает, или, если поломку тесты не увидят по построению, строка «=» с причиной в её блоке
(известная эквивалентная); строка «=» и снятый блок ослабляют проверку (CLAUDE.md § Сначала спросить). Мутация, чей
текст «было» правка кода убрала, — в отчёте: её блок переписывают под код. Проверки спецификации без тестов:
`make mutate A=--anchors` — только якоря (секунды), `A=--build` — сборка каждой мутации (минуты, без Docker),
`A=--check` — то и другое; с id — этих мутаций. Результат мутации живёт по ключу — её блок и файлы, которые она
правит: убитая с тем же ключом не гоняется заново, пока на месте тест, который её убил (правка спецификации, другого
файла или коммит мимо них полный прогон не повторяют, оборванный прогон продолжается с места); выжившие,
несобравшиеся и устаревшие идут заново всегда. Тест, ослабленный в другом файле, такой прогон не видит — поэтому
`A=--strict` (шаг релиза) берёт только вердикты прогонов того же снимка, кроме несобравшихся и таймаутов: релиз гоняет
мутации заново, оборванный строгий прогон продолжается с места; `A=--fresh` гоняет все заново.

Правка «стало», которая убирает последнее использование переменной, параметра или импорта, не собирается: оставь его
в выражении — условие `&& false` или `|| true`, срез `[:0]`, `min(n, 0)`, вызов с тем же аргументом. ID блока своего
домена — `<домен>-<код>` (`orders-12`), как у среза `make new-domain`: с кодами шаблона (`M02`, `P08`) они не
пересекаются.

Спецификация растёт с кодом: новая логика (ветвление, правило, перевод ошибок, запрос) — свои блоки в
`mutants.txt` тем же коммитом, что код, и `make mutate A="<id> …"` до коммита — убиты; срез `make new-domain`
приходит со своими блоками. Файл кода без единой мутации — Go-файл `internal/`, `cmd/` и `pkg/` с функцией
(кроме тестов, сгенерированного и `internal/testkit/`) и запросы sqlc — `make mutate`, `A=--anchors` и `A=--check`
называют. Спецификация — код сервиса: форк получает её затравкой, `make template-update` её не переносит
(`.template/paths`), prune доменов идентичности снимает их блоки.

## Anti-patterns

- ❌ Мокать `*sql.DB`/`*pgxpool.Pool` напрямую — мокай интерфейсы домена (Repository).
- ❌ Тесты на сгенерированный sqlc-код — тестируй методы Repository.
- ❌ `time.Now()` в коде — инжекть `clockkit.Clock` (детерминизм). `context.Background()` в проде — только корень процесса в `cmd/*`, не `internal/`.
- ❌ Закомментированные тесты — удаляй или фикси.
- ❌ `t.Skip` в тесте archtest — отказ до прогона (`TestMain` archtest): снять проверку гейта — правка гейта
  (CLAUDE.md § Границы), а не пропуск.
- ❌ Мок и рукописный фейк одного интерфейса одновременно.
