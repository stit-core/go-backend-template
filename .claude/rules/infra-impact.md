# Infra-impact

Репо останавливается на image-in-registry; деплой и окружение — хаб `<org>/infra`.
Изменение, требующее действия инфра-стороны, молча разъедется с прод-окружением, если его не
зафиксировать. Процедура и формат блока — skill `infra-handoff`.

Тронул инфра-поверхность → до claim «готово» / коммита оформи `INFRA-HANDOFF`-блок (skill
`infra-handoff`) и отдай его в хаб: пришёл агентом из `<org>/infra` — блок входит в твой отчёт
хабу; прямой заход — попроси юзера передать его туда. Механизм мягкий (правило + skill): блок
появится, только если ты его оформишь. Машина держит одно: `up` с эффектом для выкатки (классы
migrations-check — rule `sqlc-and-migrations`) без строки `-- infra-handoff: <…>` не пропустит
`make check`.

## Что считается инфра-поверхностью

| Класс | Триггер | Кому |
|---|---|---|
| **Env/секреты** | новый/изменённый required env-var, читаемый приложением; новый required секрет-env (JWT/OIDC-класс) | проект (compose env / `.env`, значение не коммитим) |
| **Миграция-с-эффектом** | destructive / долгий lock / data-backfill / новое PG-расширение | проект (downtime/порядок выкатки) |
| **Cross-service контракт** | новый/изменённый NATS/outbox-subject для других сервисов; breaking API/схема | проект + потребители |
| **Runtime-deps/ёмкость** | новая внешняя зависимость (Redis/S3/NATS-фича); новый сетевой порт (listener); изменённые CPU/RAM/replicas/connpool | проект |

Не-инфра: внутренняя логика, тесты, рефактор без смены env/контракта/зависимостей, code-default
тюнинг без нового обязательного ENV.

## Куда кладётся (чтобы доехало до релиза)

1. **В чат** — блок для хаба `<org>/infra` (в отчёте хабу или юзеру с явным «передай в infra»).
2. **В накопитель** `.claude/plans/handoff.md` — тем же коммитом, что изменение. Он переживает
   закрытие плана; `make release` печатает его в финальный handoff и очищает.

## Инварианты

- Блок — до claim «готово»/коммита, не после. Один блок на одно цельное изменение.
- Конкретика: имя переменной, дефолт, required-флаг, точное действие в `<org>/infra`.
- ❌ Молча закоммитить required env / миграцию-с-эффектом / cross-service-subject без блока.
- ❌ Откладывать «на релиз» — там агрегируется уже записанное; не записал → потерял.
- ❌ Самому `make bump` / `make ship` / `ssh` — выкатка идёт только из `<org>/infra`.
- ❌ Значение секрета в блок/чат — только имя ключа + факт «нужен» (`.claude/rules/env-local.md`).
- ❌ Метить инфра-задачу «готово», пока handoff не предъявлен (хабу или юзеру).

## Сигналы, что ты здесь

- `make status` → `== Infra-touch ==` не `none` (cockpit чейнит сюда).
- Правишь файл под `paths:` этого правила (оно само в контексте).
- `make release` напомнил, что накопитель пуст при инфра-изменениях.
