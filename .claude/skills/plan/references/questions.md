# Планировочные вопросы

Список для шага 1 skill `plan`. Выбирай 3–5 релевантных задаче — не задавай всё подряд.
Дизайн-вопросы задавай через `AskUserQuestion`. Если на 5+ ответ «не знаю / решай сам» —
задача недозрелая: предложи research-spike или отложить.

## Скоуп
- Что входит в задачу? Что осознанно НЕ входит?
- Это новая фича / рефакторинг / эксперимент? (Багфикс → `triage-failure`, не план.)
- Связано ли с другими PR/задачами/секциями roadmap?

## API / контракты
- Меняем существующий API? Breaking change?
- Форма ответа, коды ошибок?
- Идемпотентность нужна?
- Пагинация / фильтры / сортировка?

## Схема данных
- Меняем схему БД? (→ skill `add-migration`.)
- Прямая совместимость со старым форматом нужна?
- Backfill / data migration?
- Индексы / FK / cascade?

## Cross-domain
- Какой домен владеет логикой?
- Нужны новые порты / адаптеры? (depguard допустит без правок?)

## Безопасность
- Кто имеет право вызывать? Нужен authorizer/policy?
- Чувствительные данные в логах / outbox?
- Audit-эвент нужен?

## Интеграции
- Outbox-эвент эмитится? Кто consumer?
- Внешние API? Idempotency key?

## Тесты
- TDD для какого слоя? Integration-тест нужен? Fuzz / bench?

## Rollout / откат
- Feature-flag? Поэтапно или сразу?
- Что делать, если падает в проде? Down-миграция реально откатывает?

## Инфра-поверхность (→ секция Infra impact + skill infra-handoff)
- Новый/изменённый required env-var или Vault-секрет?
- Миграция destructive / lock / backfill / extension?
- Cross-service NATS/outbox-subject, новый порт, breaking-схема?
- Новая runtime-зависимость в `go.mod`?
