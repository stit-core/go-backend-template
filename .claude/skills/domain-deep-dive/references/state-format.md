# Формат заметки `state/<ctx>/<kind>/<slug>.md`

Память скилла — рабочее состояние знания об артефакте. **Не журнал**.

Лежит рядом со скиллом (`.claude/skills/domain-deep-dive/state/`) и
**коммитится** — общая проектная память между сессиями и
архитекторами. Не часть артефактного канона `docs/domains/` (туда
уходят зафиксированные решения, не открытые вопросы). Forward-only:
описывает только текущее открытое — не «было/стало», без дат, без
журнала прошлых сессий. Это держит `git log` чистым: коммиты в state
маленькие и тематические (например «закрыл blocker про Lifecycle
User»), а не нарратив «обсуждали такого-то».

`slug` = basename файла артефакта без `.md` (например `User`,
`UserRegistered`, `RegisterUser`, `CancelWindow`). Для `vo` из
`_shared/` — каталог `state/_shared/vo/<Name>.md`.

## Шаблон

```markdown
---
ctx: user
kind: aggregate
slug: User
ref: docs/domains/user/User.md
---

## Открытые вопросы
- Может ли существовать `User` со `Status=blocked` и `EmailVerified=false`?
- Должен ли `Lock(reason)` публиковать `UserLocked` или достаточно
  изменения `Status`? (**blocker**)

## Доменные решения
- `Email` — VO с нормализацией к lowercase (не хранить «как ввели»),
  потому что login-сравнение case-insensitive по требованию бизнеса.
- `PasswordHash` — отдельный тип, чтобы исключить случайный лог сырого
  пароля через `%v`.

## Что копать дальше
- Раскрыть `Lifecycle` после ответа на blocker — таблица переходов
  зависит от того, эмитим ли `UserLocked`.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `ctx` | bounded context (basename каталога) | избыточная подсказка + быстрый фильтр |
| `kind` | один из `aggregate`/`entity`/`event`/`use-case`/`policy`/`vo` | подсказка |
| `slug` | basename артефакта без `.md` | связь с артефактом |
| `ref` | путь к артефакту от корня репо | удобная ссылка в редакторе |

## Секции

Все три опциональны. Любая отсутствует, если содержимого нет.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — вопрос блокирует
  переход `draft → stable`. Без префикса/суффикса — открытый, но не
  блокирующий.
- Закрытый вопрос **удаляется** из секции (не зачёркивается, не
  переносится в «решено»). Если стало пусто — удалить всю секцию.
- Формулировка вопроса — falsifiable, не «исследовать X». Хорошо:
  «Может ли invariant 2 нарушиться, если `Update` вызван конкурентно?».
  Плохо: «разобраться с конкурентностью».

### `## Доменные решения`

Список неочевидных смысловых решений, которые не помещаются в
`description` / комментарии артефакта, но важны для будущих сессий.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат,
  без отсылки к прошлым попыткам.
- Если решение уже растворилось в самом артефакте (попало в `description`,
  `Invariants`, `Architecture notes` контекстного README) — удалить
  отсюда (не дублировать). State держит только то, что в артефакт
  по форме не лезет.

### `## Что копать дальше`

Список локальных «следующих шагов» по этому артефакту.

- Не путать с открытыми вопросами: «копать дальше» — задача (что
  делать); «открытый вопрос» — конкретный неясный смысл.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна
  непустая секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Артефакт удалён (каскад в SKILL.md § Удаление) → удалить файл.
  - Артефакт промоутнут в `stable` и blocker'ов нет — заметка может
    остаться, если в ней непустые `## Доменные решения` (которые не
    влезли в артефакт).

## Что НЕ хранить в заметке

- Историю изменений (это `git log`).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого артефакта (имя, status, описание — это в
  самом файле артефакта).
- Доменные термины и формулировки от модели «на всякий случай».
- Альтернативы, которые рассматривались, но забыты, — если они не
  «доменное решение» с обоснованием.
- Ссылки на внешние материалы и транскрипты — это сырьё для режима B,
  не память. Поработали → извлекли → завели stub'ы → state описывает
  открытые вопросы, не «из такого-то транскрипта».
