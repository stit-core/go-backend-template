# scaffold › field — поле через слои

**Шаг 0** — прочитай инструментом Read `.claude/rules/sqlc-and-migrations.md`,
`.claude/rules/domain-architecture.md` и `.claude/rules/tests-pipeline.md`.

Новое поле сущности существующего домена — от колонки до ответа API, одним коммитом. Колонка без
пути в код — вариант `migration`; поле в payload события — ещё и вариант `event` (смена формата — `.v2`).

## Когда применять

- «Добавь колонку `phone` в users и поле в ответ»
- «Пользователь задаёт часовой пояс в профиле»

## Когда НЕ применять

- Обязательное поле во входе существующей операции, переименование или удаление поля ответа —
  breaking API: сначала `/plan` (таблица «Маршрут задачи», CLAUDE.md).
- Заполнение существующих строк (backfill) — миграция с эффектом: тоже `/plan`.

## Шаги

### 1. Контракт поля

Одним блоком до начала: имя (Go, колонка, JSON), тип и NULL, кто пишет (вход операции или система),
ограничения (rule `domain-architecture` § Вход: длина в символах, формат, NUL), значение по
умолчанию (у новых строк — из конструктора сущности, как роль в `user.NewUser`, или из конфига —
вариант `env`; у существующих — DEFAULT колонки), какие ответы его показывают. PII в лог и payload
события не идёт.

### 2. Миграция

Вариант `migration`, номер — следующий: `ALTER TABLE <t> ADD COLUMN <c> <тип>` — NULL или
`NOT NULL DEFAULT <значение>` (без DEFAULT на непустой таблице миграция упадёт); down —
`DROP COLUMN`.

### 3. Запросы и `make gen`

Колонка — в каждом запросе `infra/postgres/queries/`, который отдаёт строку целиком (`SELECT` и
`RETURNING`), тем же порядком, что в таблице (новая — последней): тогда sqlc отдаёт модель таблицы и у
репозитория один `rowToEntity`, а запрос с забытой колонкой получает свой тип строки — сборка падает.
Пишут поле `INSERT` и `UPDATE` с новым параметром: DEFAULT колонки к новой строке тогда не
применяется, значение даёт сущность. `make gen` → `db/*.go`.

### 4. Репозиторий

`rowToEntity` переносит поле, `Insert` и `Update` передают параметр. Забытый параметр сборка не
видит — его нулевое значение затирает колонку при каждой записи; ловит integration-тест (шаг 7).
NULL-колонка в sqlc — указатель (`emit_pointers_for_null_types` в `sqlc.yaml`).

### 5. Сущность и usecase

Поле — в `entity.go`; проверка — в конструкторе и методе смены, sentinel поля — в `errors.go`, правило
— в `policy.go` (канон — `user.NewUser`, `user.Rename`). Вход операции — поле DTO домена (`dto.go`),
usecase передаёт его сущности; у частичной правки условие «нет полей» (`ErrNoUpdateFields`) и текст его
правила (`Detail` перечисляет поля) учитывают новое.

### 6. HTTP

`delivery/http/dto.go` — поле входа с тегами huma (`json`, `maxLength`, `format`); `view.go` — поле
ответа (`json` snake_case) и строка в `FromEntity`; хендлер переносит вход в DTO домена. Ошибка поля —
правило в `<домен>Errors` (422, `Field: "body.<поле>"`) и в таблицах операций, которые её отдают
(`Declare`). `make gen` → `openapi.json`: в диффе — новое поле схем.

### 7. Тесты

- `entity_test.go` — проверка поля (строка с правилом — и fuzz-свойство);
- `usecase_test.go` — порт получает сущность с полем (точный аргумент мока);
- `handler_test.go` — вход usecase и тело ответа с полем (тип ответа теста лишних полей не пропускает
  — поле и в нём); `errors_test.go` — ошибка поля в таблицах операций;
- `repository_test.go` (integration) — поле записывается и читается каждым запросом записи (`Insert`,
  `Update`) с ненулевым значением; сид-хелпер домена (у `user` — `internal/testkit/pgseed`) строит
  сущность с допустимым значением поля: на нулевом значении забытый параметр незаметен;
- `test/client/models.py` — поле в моделях e2e: они строгие (`extra="forbid"`), без поля `make e2e` и
  smoke релиза падают на разборе ответа.

### 8. Готово и коммит

Готово — по CLAUDE.md § Готово. Коммит — `feat(<domain>): <поле> <сущности>`, в теле — строка `Review:`.

## Anti-patterns

- ❌ Проверка поля в хендлере или в SQL — только сущность (rule `domain-architecture`).
- ❌ Правка `db/*.go` руками или колонка без `make gen`.
- ❌ PII поля — в лог или payload события.
