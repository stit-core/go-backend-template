# Формат заметки `state/<kind>.md`

Память скилла — рабочее состояние знания о платформенном артефакте.
**Не журнал**.

Лежит рядом со скиллом (`.claude/skills/stack-deep-dive/state/`),
гитигнор. Не часть артефактного канона `docs/stack/`. Forward-only:
только текущее открытое, не «было/стало».

Стек — 8 фиксированных singleton'ов, поэтому путь плоский:
`state/<kind>.md` (без вложений).

## Шаблон

```markdown
---
kind: messaging
ref: docs/stack/messaging.md
---

## Открытые вопросы
- Outbox-drain: один реплика-инстанс с advisory lock, или per-shard? (**blocker**)
- Subject версионирование при breaking-change — `v2.events.<x>` суффикс
  или новый subject целиком?

## Платформенные решения
- `Delivery: at-least-once` сознательно — at-most-once дешевле, но
  consumer-side idempotency у нас уже есть через EventID.

## Что копать дальше
- После решения по drain — обновить `runtime.md § Entrypoints` (один
  инстанс vs replicas) и `dependencies.md § Capacity` (replicas).
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 8 stack-kinds | подсказка |
| `ref` | путь к артефакту от корня репо | удобная ссылка в редакторе |

## Секции

Все три опциональны.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — блокирует stable.
- Закрытый вопрос **удаляется** (не зачёркивается). Пусто → удалить секцию.
- Falsifiable формулировка. Хорошо: «Нужен ли advisory-lock при
  outbox-drain, если replicas=1?». Плохо: «разобраться с drain».
- **Cross-kind blocker** (drift между kit-артефактом и роллапом
  `config`/`runtime`) — частый случай для стека. Помечать в state того
  роллапа, который недополучил: `state/config.md` → «`auth` объявил
  `JWT_PUBLIC_KEY` — добавить в Required env (**blocker**)».

### `## Платформенные решения`

Список неочевидных смысловых решений, не влезших в артефакт по форме.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было/стало», без дат.
- Если решение уже растворилось в самом артефакте (попало в текст
  секции, в `Architecture notes`) — удалить отсюда.

### `## Что копать дальше`

Список локальных «следующих шагов».

- Не путать с открытыми вопросами: шаг — задача, вопрос — неясный смысл.
- При выполнении — удалить строку. Пусто → удалить секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать.
- **Перезаписывается** свободно.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Артефакт удалён (редкий кейс для стека — артефакты singleton'ы) →
    удалить файл.
  - Артефакт промоутнут в `stable` без blocker'ов — заметка может
    остаться только если в ней непустые `## Платформенные решения`.

## Что НЕ хранить

- Историю изменений (это `git log`).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого артефакта (env-имена, subject'ы, числа capacity
  — это в самом файле артефакта).
- Подсказки от модели «обычно делают так-то на проде» — это не решение
  архитектора, не пишем.
- Ссылки на compose.yaml / k8s manifest, из которых разбирали —
  это сырьё режима B, после разбора артефакт его поглотил.
