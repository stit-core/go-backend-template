# Skill: stack-deep-dive

Проектирование платформы сервиса: минимальные драфты 8 артефактов `docs/stack/` (frontmatter и H2 шаблона) →
`status: stable` с непустой секцией `Generates` в каждом. Домены (соседний strategy-репо, скилл
`/domain-deep-dive` там) отвечают «какая бизнес-логика», этот скилл — «на какой платформе она крутится»: runtime,
env, киты `golibinfra`, subjects, как версионируется и деплоится образ.

Артефакты — source of truth и вход `de-template`: `Generates` называет, что из артефакта родится в коде (module
path, `internal/platform/*`, композиция `cmd/api`, `.env.example`, киты). Канон kinds и обязательных H2 —
`docs/stack/README.md`, маппинг `Generates` → код — `.claude/skills/de-template/references/wiring.md`: скилл их
исполняет, а не пересказывает. В онбординге `/init-service` зовёт его первым этапом, затем — `de-template`.

## Главный ритм: AskUserQuestion

Скилл — интервьюер архитектора, а не редактор: архитектор принимает платформенные решения (runtime, киты, env,
subjects, ёмкость), скилл пишет их в артефакт дословно и не сочиняет. Шаг сеанса — раунд `AskUserQuestion` (до 4
вопросов, больше — следующим раундом) → ответ → `Edit` артефакта сразу, а не в конце волны: ответ, не записанный до
`/clear`, потерян. Опции — для anti-patterns, enum-полей, тест-критерия kind'а и выбора из известного; значения —
имя сервиса, module path, имена env и subjects, числа — только свободной формой (Other). «Обычный» env
(`HTTP_ADDR=:8080`) или решение «как в других сервисах» — тоже решение архитектора: сомневаешься — лишний раунд,
а не догадка. Правила вопросов — `references/workflow-patterns.md`, раздел «Стиль вопросов: правила».

## Точки входа

| вызов | поведение |
|---|---|
| `/stack-deep-dive` | сводка состояния 8 артефактов + AskUserQuestion: что углубить / что заводить (если каких-то нет) |
| `/stack-deep-dive <kind>` | завести/углубить артефакт указанного kind: режим A (если файла нет) или режим C (если есть) |
| `/stack-deep-dive <свободный текст / приложение>` | сырьё → разбор (режим B) |

`kind` ∈ {`service`, `runtime`, `config`, `persistence`, `messaging`,
`auth`, `observability`, `dependencies`} — фиксированные 8 singleton'ов.

## Что делать сразу при запуске

1. Прочитать `docs/stack/README.md` — освежить канон (8 kinds,
   обязательные H2, контракт `Generates`).
2. Если args пустые — сделать сводку и через `AskUserQuestion`
   предложить выбор.
3. Если args указывают на kind — определить режим (A — нет файла, C —
   есть), применить маршрут из `references/workflow-patterns.md`.
4. Если args = сырьё (свободный текст / приложение) — режим B.

## Сводка состояния

1. `ls docs/stack/` — какие из 8 файлов уже есть.
2. Для каждого присутствующего файла: прочитать frontmatter (`status`,
   `kind`) и H2-заголовки; считать заполненность обязательных секций
   (см. `references/field-checklists.md`).
3. Прогнать `make validate-stack-docs A=--stable`: зелёный — все 8 на месте
   и stable, выйти: «стек спроектирован, делать нечего». Иначе он называет,
   каких kind'ов нет и что не stable; заведение недостающих — первый шаг.
4. Прочитать `state/` (если есть) — `## Открытые вопросы`; пометки
   `**blocker**` приоритетны.
5. Сжатая карта в чат:

   ```
   ## Состояние docs/stack

   | kind | файл | status | H2 заполнено | дыры |
   |---|---|---|---|---|
   | service | ✅ | draft | 2/4 | Versioning, Generates |
   | config | ✅ | draft | 1/5 | Optional, Secrets, Validation, Generates |
   | runtime | ❌ нет | — | — | — |
   …
   ```

6. Через `AskUserQuestion` — что копать дальше (опции = существующие
   draft-артефакты + «завести недостающие»).

## Режимы

A — заведение (файла kind'а нет: копия `_templates/<kind>.md`, frontmatter, фраза назначения → C); B — сырьё
(compose.yaml, k8s-манифест, `main.go`, заметки → решения по kind'ам, план в чат, по подтверждению — правки → C);
C — углубление (вопросы по дырам, волнами фундамент → роллап, чек-лист stable после каждой правки). Шаги —
`references/workflow-patterns.md`.

## Inside-out волны (порядок копания)

Запоминается в скилле, у архитектора не спрашивается. Фундамент → производное;
два роллап-артефакта (`config`, `runtime`) идут последними, т.к. собирают
решения предыдущих:

1. `service` — идентичность: имя, module path, версионирование, бинари.
2. `dependencies` — какие kit'ы golibinfra, внешние runtime-deps,
   ёмкость.
3. `persistence` — Postgres: driver, миграции, kit-таблицы, пул.
4. `messaging` — published/consumed subjects, delivery semantics.
5. `auth` — идентичность (`own` / `external`), authn/authz, authgate, роли,
   seed-admin, brute-force.
6. `observability` — логирование: режим вывода (stdout), формат,
   уровни, структурные поля.
7. `config` (роллап) — required/optional env, секреты, валидация —
   собирает все envconfig-теги из подключённых kit'ов и решений 1–6.
8. `runtime` (роллап) — entrypoints в `cmd/api` (HTTP / outbox-drain /
   NATS-subs / jobs), lifecycle, shutdown — собирает реально
   поднимаемые подсистемы из 1–6.

Юзеру в начале волн — короткое: «иду фундамент → роллап, начну с
service; скажи если хочешь прыгнуть в конкретный kind».

## Память `state/<kind>.md`

Рабочая память скилла рядом с ним (`.claude/skills/stack-deep-dive/state/`), коммитится: открытые вопросы
(`**blocker**` держит stable), платформенные решения, которые не ложатся в артефакт по форме, что копать дальше.
Пустая заметка удаляется, история не копится (forward-only). Формат — `references/state-format.md`.

## Контракт `draft → stable`

Чек-лист после каждой правки — `references/draft-stable.md`: обязательные H2 заполнены, `Generates` конкретна,
cross-kind sync согласован, `make validate-stack-docs` зелёный, тест-критерий kind'а подтверждён в этой сессии,
`state` без `**blocker**`. Все шесть — `AskUserQuestion` «Готов к stable, повышаем?», по «Да» — `status: stable`.
Сам скилл не повышает и не понижает.

## Cross-kind sync

Решения kit-артефактов (`auth`, `persistence`, `messaging`, `observability`, `dependencies`) роллапятся в `config`
(env, секреты) и `runtime` (подписчики, jobs, хуки остановки). После каждой правки kit-артефакта скилл дописывает
роллап черновиком и показывает дифф через `AskUserQuestion`: «вот что добавилось — окей?». Что куда — раздел
«Cross-kind» kind'а в `references/field-checklists.md`; без sync de-template разворачивает неполный скелет.

## Завершение сессии

1. Перечислить затронутые артефакты (заведены / углублены / промоутнуты).
2. Перечислить нерешённые `**blocker**`-вопросы (читая `state/`).
3. Прогнать `make validate-stack-docs` —
   подтвердить зелёный.
4. Предложить следующий шаг:
   - онбординг (пришёл из `/init-service`): 8/8 stable → дальше `/de-template`;
   - отдельно (стек уже жил, поменялся): артефакты теперь актуальный
     source of truth; если правка задевает инфра-поверхность (таблица
     rule `infra-impact`) — оформи через `/infra-handoff`
     для хаба `<org>/infra`.

## Запреты

- Не редактировать артефакты вслепую — всегда сначала `Read`.
- Не выдумывать платформенные решения: anti-pattern как опция — да; имя env, subject, путь, конкретное число —
  только от архитектора.
- Не оставлять `Generates` пустой или с заглушкой: артефакт без конкретной `Generates` не становится stable.
- Не дублировать здесь правила `docs/stack/README.md` и шаблонов — скилл их исполняет.
