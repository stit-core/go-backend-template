# Contributing — работа с шаблоном через Claude Code

**[META]** Для контрибьютора *самого шаблона*: как устроена `.claude`-система, что
enforce'ится детерминированно, как вмешаться. (Онбординг форка — `/init-service`.)

## Что где лежит и когда грузится

| Слой | Где | Когда грузится | Сила |
|---|---|---|---|
| Ядро + роутер | `CLAUDE.md` (реальный файл) | всегда, каждый запуск | advisory |
| Path-scoped правила | `.claude/rules/**/*.md` с `paths:` | после Read, Write или Edit matching-файла и его чтения командой Bash (`cat`, `head`) — первую запись нового файла не застаёт | advisory |
| Skills (процедуры) | `.claude/skills/<name>/SKILL.md` | по `description` или `/<name>` | procedural |
| Settings / permissions | `.claude/settings.json` | старт сессии | детерминированно (deny) |

Progressive disclosure: на холодном старте — только имена+описания; тела skills/rules и
`references/` грузятся по необходимости.

**Важно про `paths:`** — нативный ключ path-scoping в Claude Code именно `paths:` (не
`globs:`). Правило без `paths:` грузится всегда. Проверь, что новое правило path-scoped.

## Цикл одной задачи

```
prompt → /smartdev (cockpit: make status, читает активные планы, чейнит режим)
       → маршрут (CLAUDE.md § Маршрут задачи: triage-failure / plan / scaffold / напрямую)
       → act (меняется поведение — тест первым; инфра-поверхность задета → infra-handoff)
       → готово (CLAUDE.md § Готово)
       → commit (Conventional Commits)
```

Планы — файлы `.claude/plans/<slug>.md`, бэклог — `.claude/plans/backlog.md`; закрытый план
удаляется (история в git).

## Кто что enforce'ит

| Механизм | Где | Сила |
|---|---|---|
| git-хуки | `scripts/git-hooks/` (подключает `make setup` через `core.hooksPath`): commit-msg (Conventional Commits, subject до 72 символов при любой локали, строка `Review:` в теле `feat`, `fix` и переноса обвязки `chore(template)` — `TestCommitMsgHook`; отказ `git cherry-pick --continue` и `git commit` посреди `rebase` говорит, как дописать сообщение перенесённого коммита и закончить перенос; не видит, что написано в `Review:`, строку под линией ножниц `git commit -v` — git её обрежет, коммиты `cherry-pick` без конфликта и коммиты `git rebase --continue` — их git хуку не показывает, их сообщение проверяет pre-push), pre-commit (fmt-check+vet+lint+validate-stack/plan снимка индекса в своём worktree `.cache/index-snapshot/wt` — его, после копии или переноса репо, хук создаёт заново: правка дерева вне индекса и неотслеживаемое на вердикт не влияют — `TestPreCommitChecksIndex`), pre-push (каждый пушимый коммит — его нет ни в ветках remote'ов, ни — при push'е в пустой remote, и с тегами, — под тегами шаблона `template/*`; пустой — без единого ref'а (`git ls-remote`), в непустой remote тег шаблона — выпуск, его коммиты судятся, и по URL в новую ветку тоже; секрет в дереве коммита — отказ, перечнем `TestNoSecretFiles` (remote получает и промежуточный коммит, чей секрет убрал следующий), сообщение — хуком commit-msg из дерева его родителя: правилом, по которому коммит делали, старые коммиты не судятся; аннотация тега выпуска — в формате разделов переноса обвязки (`TestTemplateAnnotation`); затем `make check` каждого пушимого ref'а — его верхнего коммита — в свежем worktree: незакоммиченное и игнорируемое на вердикт не влияет) | **детерминированно** |
| permissions.deny | `.claude/settings.json` | **детерминированно** (блок `--no-veri…` где угодно в команде — и сокращение, и в кавычках, force-push, reset --hard, правка `*.pem`/`*.key`/generated); чтение `.env`/`.env.local` — только для инструмента Read: `cat` и другие команды Bash deny не видит, их держит правило (CLAUDE.md, rule `env-local`); снятый запрет — отказ `TestGuardWired`. allow — только то, что не пишет (чтение `find` и `git branch` Claude Code пускает без вопроса сам), раздела `ask` нет: он спрашивает человека в любом режиме, и в bypass (`TestAllowReadsOnly`) |
| Хук Claude Code | `.claude/hooks/guard-bash.sh` (PreToolUse, Bash) | барьер от случайного обхода, не песочница — «guard-bash» ниже |
| Самопроверка обвязки | `internal/archtest/harness_test.go`, `internal/archtest/guard_test.go`, `internal/archtest/template_test.go`, `internal/archtest/onboarding_test.go`, `cmd/api/main_test.go`, `cmd/api/boot_test.go` (шаг тестов) | **детерминированно** — «Самопроверка обвязки» ниже |
| Самозащита гейта | `Makefile` (`make check`), pre-push, `TestMain` archtest | **детерминированно** против флагов, переменных вызывающего и обычных форм лишнего makefile (`make check` не запускается с `-i`/`-k`/`-n`/`-p`/`-q`/`-t`/`-j`, `--eval` и `-E`, подменой своих переменных (и `override`), `GOFLAGS` и `API_TEST_MAIN_ARGS` — отказ и при разборе `Makefile`, и первой строкой рецепта `check::`, какой бы целью до него ни дошли; `MAKECMDGOALS`, `MAKEFILE_LIST` и `MAKEOVERRIDES` от вызывающего (командная строка, окружение) — отказ make для любой цели; лишний makefile с `check:` — ошибка разбора, прочитанный до `Makefile` или из `MAKEFILES` — отказ при разборе, после — отказ первой строки рецепта, она сверяет состав makefile'ов при любых флагах; `TestMakeCheckCannotBeForged`); cover-check читает профиль только своего прогона — `coverage.out` гейт снимает до шагов (`TestCheckCoversItsOwnRun`). Окружение оболочки вызывающего до шагов не доходит: `BASH_ENV`, `SHELLOPTS`, `BASHOPTS`, `CDPATH`, `GLOBIGNORE` и экспортированные функции `Makefile` снимает с рецептов, хуки стартуют `bash -p` и снимают переменные make, а проверки идут через make (`TestGateStepsIgnoreShellEnvironment`, `TestHooksIgnoreCallerEnvironment`). Makefile, написанный под подделку (переприсваивает `MAKEFILE_LIST`, задаёт `GATE`, `.IGNORE` или `SHELL`), обходит любую сверку внутри make: свой makefile — правка гейта, как правка хуков (CLAUDE.md § Сначала спросить). Вердикт для remote — pre-push: `make check` пушимого коммита в свежем worktree, без переменных make и оболочки из окружения пушащего и makefile'ов вызывающего (`TestPrePushGatesPushedCommit`); `make release` гонит `make -f Makefile check` и smoke чистого дерева, шаги гейта читают тот же `Makefile` — свой `GNUmakefile` (и игнорируемый git) их не подменяет (`TestReleaseGateIgnoresGNUmakefile`). Тест archtest не пропускается: `Skip`, `SkipNow` и `Skipf` в пакете — отказ `TestMain` до прогона; ранний `return` в тесте (как и другую правку теста, после которой он проверяет меньше) машина без разбора потока от законного выхода не отличит — это правка гейта (CLAUDE.md § Сначала спросить), её держит ревью диффа |
| Path-scoped rules | `.claude/rules/**/*.md` | контекстная подсказка |
| CLAUDE.md | repo root | always-on advisory |

Хук Claude Code в шаблоне один — `guard-bash` против обходов git-хуков и гейта; остальные
критичные инварианты держат git-хуки + `permissions.deny`; soft-guidance — CLAUDE.md и rules.
Push в `main` разрешён (прямой или через PR); gate — `pre-push → make check`.

### guard-bash

Блокирует:
- `git commit -n`, `--no-veri…`, `send-pack` — и со словом в кавычках (`$'…'` тоже), бинарём подкоманды
  (`git-commit`, `/usr/lib/git-core/git-send-pack`; у «читателя» без подстановки — `man`, `ls` — это данные; пейджер
  и браузер `man` — `-P`, `--pager`, `-H`, `--html`, `MANPAGER`, `PAGER` — код) или
  кодом для оболочки: `eval` и оболочка (`sh`, `bash`, `dash`, `zsh`, `ksh`, `ash`, `mksh`, `csh`, `tcsh`, `fish` — и с
  каталогом, обёрткой и опциями) с `-c` или `-s`, справа от `|`, с heredoc или here-string (`bash -e -c`,
  `| sudo bash -x`, `sh<<<'…'`), и git, исполняющий строку из значения: вложенный git в кавычках или после «=» команды
  с git (`git rebase --exec=…`, `git submodule foreach`, `git bisect run`, `git filter-branch`, `git -c core.editor=…`,
  `GIT_SEQUENCE_EDITOR=…`), кроме текста сообщения и поиска по истории (`-m`, `--grep`, `-S`, `-G`, `--format`,
  шаблон `git grep` без `-O`); значение — своей команды: текст `grep` или `echo` в конвейере и списке — данные, а
  присваивание в строке с git (`VAR=…`, `export VAR=…`) — значение, которое git исполнит;
- `SKIP_PREPUSH` и `hooksPath` в любой команде;
- алиасы и include конфига git в команде (`git -c alias.…`, `git config include.path …`, `GIT_CONFIG_KEY_0=alias.…` —
  и значением в кавычках: `-c 'alias.c=commit -n'`); снятие секции `core` (`git config --remove-section` или
  `--rename-section core`);
- команду с путём `scripts/git-hooks`, хука или `.git/config` (и с `//`, `/./` и `<каталог>/..`), в которой не узнано
  чтение: запись перенаправлением, команды-писатели (`chmod`, `rm`, `mv`, `tee`, `cp` в хук), текст `echo` и `printf`
  рядом с оболочкой-интерпретатором (`echo '…' | bash`) и «читатели» с опцией или программой, которая пишет или
  запускает (`sed -i` и скрипт `sed` с каталогом хуков или `.git/config`, программа `awk` с `>`, `|` или `system`,
  `sort -o`, действия `find`, `git … --output`, `rg --pre` — `--pretty` читает, значение `git -c` и переменной
  окружения с таким путём).

Формы — `internal/archtest/testdata/guard-cases.txt`, `TestGuardBash`; подключение хука и `disableAllHooks` — и в
локальном `.claude/settings.local.json` клона, где он есть, — `TestGuardWired`.

Не видит, в том числе:
- то, что подставит оболочка (`$G`, `$(…)`, `<(…)`, и в двойных кавычках), экранирование в `$'…'` (`$'\x2dn'`),
  раскрытие скобок (`{bash,-c,…}`), glob и `xargs`;
- `chmod -R` и `find … -exec` с каталога выше хуков; файл без пути после `cd` (`cd .git && … config`);
- код других интерпретаторов и команд, исполняющих строку (`python3 -c`, `perl -e`, `trap`, `su -c`, `watch`), скрипт
  из файла и со stdin текущей оболочки (`bash <файл>`, `source <файл>`, `source /dev/stdin`), запись в хук текстом,
  который оболочке передаёт не `echo` и не `printf` (`cat <<< 'chmod -x <хук>' | bash`), команду, которую «читатель»
  исполняет из своих данных (`sed … e`), из конфига git или окружения без пути хука и вложенного git в ней
  (`git -c core.pager=<скрипт>`, `GIT_EDITOR=<скрипт>`);
- алиас и include из файла конфига, записанного мимо `git config` (`~/.gitconfig`, `GIT_CONFIG_GLOBAL=<файл>`);
  кавычку, открытую строкой выше, и маркер heredoc внутри кавычек;
- push из свежего клона, из другого каталога (`git --git-dir=<репо>/.git push`) и из worktree на коммите без каталога
  хуков (хуков там нет); коммит plumbing-командами (`git commit-tree` с `update-ref`); инструменты гейта, подменённые
  через `PATH`;
- правку инструментами Edit и Write — такой обход — правка гейта (CLAUDE.md § Сначала спросить).

### Самопроверка обвязки

Проверяет детерминированно, шагом тестов:
- ссылки прозы: make-цели, пути — от корня репо или каталога документа — и файлы, пути API, скиллы, правила (каждое
  имя перечня) и тесты (`TestИмя`) существуют, неотслеживаемый файл — отказ с подсказкой `git add`; якорь
  «`<файл>.md` § раздел» ведёт на заголовок (нумерованный — и по имени) или жирную метку, цель markdown-ссылки и
  её `#якорь` есть; состав и порог `make check` в CLAUDE.md — те, что в рецепте; типы коммитов CLAUDE.md — те, что
  в хуке;
- доставку правил и скиллов: шапка правила и скилла разбирается так, как её читает Claude Code, glob'ы `paths:`
  правил ложатся на файлы репо, правило без `paths:` — отказ, `name:` скилла — его каталог, reference scaffold,
  `triage-failure` и `infra-handoff` начинаются с «Шаг 0» — Read своих правил;
- подключение: модуль, HTTP- и NATS-входы каждого домена — в `cmd/api`; kit-таблицы графа, в том числе outbox
  доменов, — источники `cmd/migrate`; required env конфигов — в `.env.example`;
- обвязку шаблона: пути `.template/paths` есть, тег обвязки на HEAD = `.template/version`, `make template-update`
  переносит обвязку в форк, маркеров конфликта в репо нет; пути `.template/identity` есть, prune называет каждый
  файл, который знает их пакеты; канонический репо шаблона (origin) — с module path шаблона и без артефактов стека;
  валидатор stack отвергает шаблоны как есть.

Не видит: опечатку в первом сегменте пути, ссылку простым текстом и якорь файла, имя которого в репо не одно; у
форка — раздел его файла, на который ссылается проза шаблона (`SECURITY.md` переписывает de-template), его сверяет
канонический репо шаблона; у проекта с внешней идентичностью — мёртвые имена тестов и glob'ы в файлах шаблона
(путь есть в теге `template/v*` или в первом коммите форка), и после правки форком.

Цена правил для законной работы: Bash-команду со словом `SKIP_PREPUSH` или `hooksPath` guard
отклоняет — поиск инструментами Read и Grep, сообщение коммита с ними — heredoc (`git commit -F -`);
оболочка-интерпретатор в команде (`bash -c`, `eval`, `| bash`, слово `sh` или `bash` справа от `|`)
снимает кавычки со всей строки, и `git commit -m "… -n …" && bash -c '…'`,
`echo "pre-push …" && bash -c '…'`, `grep "… | sh …" <хук>` — отказ: такие команды — отдельными
вызовами, шаблон — инструментом Grep, сообщение коммита с формами обхода — heredoc; путь хука и
`.git/config` читают `cat`, `head`, `grep`, `sed -n`, `git diff` и другие команды списка guard — отказ
получают чтение командой вне списка (`nl`, `od`, цикл `for`), `cp`, `sort`, `find` и `awk` со словом,
которое раскроет оболочка (`$X`, `{a,b}`, glob), и переменная окружения с таким путём; флаг make из
окружения (`MAKEFLAGS=-j8`) `make check` отвергает — запуск `MAKEFLAGS= make check`.

## Версия обвязки

Форк получает обвязку шаблона git-способом: `make template-update`, процедура — skill `/upgrade`.

- `.template/paths` — пути шаблона, строка — путь или `:(exclude)<путь>`: обвязка агента,
  инструменты и гейт, самопроверки, сборка образа (`Dockerfile`, `Dockerfile.migrate`,
  `.dockerignore` — контракт с `scripts/release.sh` и его тестами), доки шаблона. Остальное — код
  форка: правки шаблона там тег называет в разделах `Безопасность` и `Платформа` с путями, форк берёт
  их тем же переносом по запросу (`make template-update TO=… PATHS='<пути>'`) или отказывается
  (`PATHS=-`) — с причиной в теле коммита переноса (skill `/upgrade`). Решение — до переноса: после него
  код интервала движок не возьмёт, поэтому без `PATHS` при таких пунктах он отказывает.
- `.template/version` — версия обвязки, имя тега `template/vX.Y.Z`: коммит выпуска несёт этот тег,
  следующие коммиты — ту же версию до нового выпуска. Форк получает её при создании,
  `make template-update` сдвигает её вместе с обвязкой. Первый перенос форка идёт от коммита
  шаблона, из которого форк создан (по дереву его первого коммита): кончик `main` обычно новее тега.
- Тег обвязки — аннотированный `template/vX.Y.Z` на коммите `main`, где `.template/version` — имя
  этого тега (иначе archtest `TestTemplatePaths` не пустит push тега). Релизы образа — теги
  `vX.Y.Z`; теги обвязки `make release` не видит.
- Версия: minor — новое и breaking для форка, каждое breaking — со шагом в аннотации; patch —
  исправления без новых требований к форку.
- Выпуск — с OK владельца (тег и push — CLAUDE.md § Границы) и до `make release` шаблона: блоки
  накопителя `.claude/plans/handoff.md` в дереве тега форк берёт за перенесённое (skill `/upgrade`), а релиз
  его очищает. Новая `.template/version` коммитом `meta(template): template/vX.Y.Z` →
  `git tag -a --cleanup=verbatim template/vX.Y.Z -F <аннотация>` (без `--cleanup=verbatim` git снимает строки на
  `#`) → `git push origin main template/vX.Y.Z` (pre-push гонит `make check` на пушимом коммите с тегом). `main`,
  где `.template/version` называет ещё не выпущенный тег, уходит в origin только с этим тегом на
  HEAD: иначе форк с такого `main` создан раньше тега своей версии, и правки до тега придут к нему
  только переносом до следующего тега.
- Тег выпуска проходит самопроверку прозы на своём дереве (pre-push): всё, на что ссылается проза, в
  нём есть — тег — запасной источник образцов доменов идентичности у форка без них (CLAUDE.md
  § Проектирование первично).

Аннотация — как у golibinfra, по разделам; пустой раздел не пишется:

```
template/vX.Y.Z

<вступление прозой — по желанию>

Breaking:
- <что изменилось> → <что форк делает руками>

Гейт:
- <новая или более строгая проверка> → <как привести к ней код форка>

Безопасность:
- <фикс вне путей шаблона — домены идентичности, internal/platform, cmd: что чинит и чем грозит
  без него> → PATHS='<пути>'

Обвязка:
- <правила, скиллы, доки, скрипты — приходят переносом>

Платформа:
- <остальная правка вне путей шаблона: internal/platform, cmd, pkg, конфиги> → PATHS='<пути>'

Как обновиться:
1. <команды переноса по порядку, когда их больше, чем make template-update TO=… PATHS=…>
```

Фикс безопасности вне путей шаблона — пунктом `Безопасность`, а не `Платформа`: форк со своей
идентичностью обязан его перенести или отклонить с причиной. Пункты этих двух разделов движок переноса
печатает и требует по ним решения (`PATHS` или `PATHS=-`): раздел — строка `Безопасность:` или `Платформа:`,
пункт — `- …` с продолжением отступом, конец раздела — пустая строка. Вид аннотации сверяет pre-push тега выпуска
(`TestTemplateAnnotation`): после вступления каждый абзац начинается строкой раздела ровно в этом виде, в разделе —
пункты, шаги `1. …` и продолжения с отступом, а во вступлении нет строки, похожей на заголовок (имя раздела в
начале — с двоеточием, другим знаком или без, — или до трёх слов с двоеточием на конце); иначе — отказ с образцом:
заголовок с опечаткой, отступом или маркером и абзац пунктов без заголовка перенос пропустил бы вместе с пунктами.

## Troubleshooting

| Симптом | Куда смотреть |
|---|---|
| Skill не активируется | `description` в frontmatter: ключевой сценарий первым, категории намерений вместо списка фраз; `description` + `when_to_use` ≤ 1536 символов (дальше листинг обрезает) |
| Path-scoped rule не грузится | правило приходит после первого обращения к файлу (Read, Write, Edit, `cat`, `head`), а не до — нужно раньше: прочитай само правило через Read; frontmatter `paths:` (не `globs:`!) и glob держит archtest `TestRulesAndSkillsLoad` |
| CLAUDE.md игнорируется | длина >200 строк, либо конфликт инструкций между секциями |
| Коммит reject'нут | `scripts/git-hooks/commit-msg` — тип из CLAUDE.md § Git workflow, subject ≤72, у `feat`, `fix` и `chore(template)` — строка `Review:` в теле (CLAUDE.md § Готово); перенос чужого коммита — дописать сообщение `git commit -e`: у `cherry-pick` в цепочке ещё коммиты — `git cherry-pick --continue`, у `rebase` — всегда `git rebase --continue` |
| `make gen` / `gen-check` падает | queries ссылаются на несуществующие колонки / забыл `make gen` после правки интерфейса или HTTP-операции (`openapi.json`) / `моки разошлись с кодом` — mockery обновил их в дереве: обновлённые — в коммит, ручная правка мока не живёт / `новые моки не в индексе` — `git add` |
| archtest: `golangci-lint linters --json` не запустился | golangci-lint нет в PATH — `make setup` (pinned-версия) |
| `make lint` → `FAIL: golangci-lint exit N` | линтер не отработал, причина — в хвосте вывода: 3 — конфиг или неизвестный линтер, 4 — таймаут, 5 — нет Go-файлов, 7 — ошибка в логе (например, пакет не найден) |
| Замечания lint по файлам, которых нет | кеш анализа своего дерева — `.cache/golangci-lint`; удалить каталог |
| `validate-plan` / `validate-stack` падает | структура артефакта — см. соответствующий `README`/skill |
